# 客户智能经营工作台

2026-11-09 实施。首页围绕新客户准入与老客户增长组织；原真实数据工作台位于 `/data`，既有客户详情、洞察、历史入口保留。

## 已实现

- 经营总览：飞书客户与商机只读加载；按历史实际成单贡献和当前机会分层，可点击筛客户。
- 新客户核查：服务端精确匹配企查查存档；可选实时查询适配。显示主体、小微属性、规则分、拦截/复核理由、来源时间和规则版本。
- 需求雷达：公开公告手工导入、重复来源检查、截止日期检查、四类需求匹配、能力依据和适用条件展示；中标结果、过期、未来日期与普通新闻分别标注。
- 能力库：根据用户提供的燕云、神州知了和 DIG 能力资料整理，保留产品/案例/POC成熟度说明。
- 需求详情直接打开匹配客户档案与飞书源记录；按用户要求移除独立经营行动页面、领取跟进和准入复核行动入口。原浏览器行动存档保留，不再展示。
- 实际与演示工作空间分别保存，演示不调用实时核查。未配置数据源时不自动填入假数据。

## 真实数据边界

客户与商机来自既有 `/api/dig/overview`，不写入飞书。导入公告和暂不跟进反馈仅保存在当前浏览器 localStorage，不构成服务端共享台账、正式授权或审计系统。

自动准入政策固定关闭。示例分为试点规则分，不是企查查信用评级；未完整返回的风险项不作为零风险。没有合同/授信/业务条件规则，因此真实结果始终交由复核，不替代审批。

分层仅使用当前可访问商机的实际成单金额；不是财务确认收入。正金额中位数为贡献阈值；无金额客户不代表低价值。当前机会根据源状态、阶段、实际成单日期保守排除关闭/签约记录，需业务确认状态口径。

能力匹配是确定性关键词规则，不调用大模型。完整客户名命中仅作为关系提示；代理机构、集团子公司及招标资格仍需核实。系统不向外部人员发送消息，不自动认定商机。

## 实时企查查配置

在服务端 `.env.local` 配置：

```
DIG_QCC_LIVE_ENABLED=true
DIG_QCC_API_KEY=实际账号
DIG_QCC_API_SECRET=实际密钥
```

用户点击提交客户核查时才请求一次官方 `RiskControl/Scan`，不自动重试，不批量查询。可能产生供应商查询费用。未启用时读取原缓存。真实适配尚未用付费账号联调：需确认账号权限、响应字段和必查项口径，缺少字段时强制复核。密钥不发送到客户端。

## 需求订阅配置

`DIG_SIGNAL_FEED_URL` 为业务确认授权的服务端数据源地址；可选 `DIG_SIGNAL_FEED_TOKEN`。返回 JSON 数组：

```json
[{"id":"provider-project-001","customer":"采购主体完整名称","title":"数据治理采购意向","text":"公开需求原文摘录","url":"https://public-source.example/notice/001","published":"2026-11-09","deadline":"2026-12-01","kind":"采购意向"}]
```

kind 支持采购意向、招标公告、公开动态、中标结果。接口过滤非法记录；最多1000条。浏览器打开期间每5分钟刷新，也可手动刷新。不包含后台定时抓取器、全网监控或飞书消息发送，配置前显示未连接。外部采集服务应负责授权、公告项目ID、更正合并、限流和来源更新。

## 本地体验与演示

```
cd src/frontend
npm run dev -- --hostname 127.0.0.1
```

首页默认真实数据；右上角切换“评选演示 · 合成数据”。演示路线：新客户准入（完整、小微、缺失、风险、注销）→ 增长机会雷达 → 数据治理候选证据 → 查看客户档案 → 打开飞书源记录。记录刷新保留，刷新后默认回到真实模式，切回演示可继续。

## 客户资产总览更新

首页改为客户资产总览，保留客户价值分层独立入口。总览支持部门、关联销售员、行业、地区、客户级别筛选；展示客户规模、历史成单覆盖、商机关联、省级覆盖、核心字段完整率与销售员数。地图按客户城市归省，点击省份展开地区销售员与客户；点击销售员进一步筛客户，客户可打开原档案和飞书源记录。多人销售字段拆分统计，同一客户同一销售员去重。行业、地区条形图和客户级别环形图均可交互。新增趋势、标准化率和独立客户类型缺少可靠源字段时不推算。

浏览器已验证真实湖北省36家客户、11名关联销售员，选中徐赟筛出14家客户，并可打开客户合作档案。地区依据源城市字段，不根据企业名称推断真实所在地。
