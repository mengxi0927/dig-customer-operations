# 本地真实客户经营工作台

2026-11-09：首页已切换为真实数据只读工作台，保留蓝灰视觉、客户与商机搜索、负责人筛选、分页及详情。首页不再导入 prototype/demo-data，不读取原型 localStorage，任务、收入、成本、毛利、续约和协同不使用合成数据填充。

## 来源

- `/api/dig/overview`：既有飞书客户及商机主表全量读取，60 秒缓存，按签约客户记录 ID 关联。原始商机阶段和状态均保留。
- `/api/dig/qcc`：使用 `pg` 直读 customer-db 的 `qcc_search_cache` 和 `customer_aliases`；连接及事务均设置只读，连接超时 5 秒，查询超时 10 秒。仅读取现有缓存，不调用企查查查询、刷新或写入接口。
- 同一路由的风险部分通过服务器已有 `/api/risk-assessments` 获取保存的评估，仅接受 provider=企查查、data_source=real。风险源独立失败不阻止工商缓存和飞书展示。

数据库中的搜索候选不等于已确认客户。客户匹配优先明确的 feishu_record_id，否则仅使用 Unicode NFKC 规范化、trim 后的完整企业名；不删除公司后缀、不猜测简称，多个信用代码冲突时不关联。同一主体缓存取最新，过期明确提示。风险按信用代码或完整企业名匹配，未评估不能标为低风险。

本次核验：飞书客户 1,621、商机 2,084；数据库查询缓存 39 条，解析得到 26 条工商候选/详情，只有 3 家客户可明确匹配工商；保存的真实风险评估 10 份。这些数量随来源变化，界面不写死。工商及风险存档列表支持核对未匹配企业。

## 运行

在 `src/frontend/.env.local` 配置服务端环境变量（文件已 Git 忽略）：既有 FEISHU_*、DIG_DATA_ACCESS=local、QCC_DATABASE_URL、QCC_RISK_BASE_URL。禁止使用 NEXT_PUBLIC 存储凭据。

数据库未公开端口。本机通过仅绑定 loopback 的 SSH 隧道连接：

```sh
ssh -N -o ExitOnForwardFailure=yes -o ServerAliveInterval=30 \
  -L 127.0.0.1:15433:172.18.0.3:5432 user@10.126.50.207
```

`172.18.0.3` 是核验时 customer-db 容器地址，容器重建后需通过 `sudo docker inspect` 检查最新地址。QCC_DATABASE_URL 使用服务器现有数据库账户和库名，主机改为 127.0.0.1:15433。密码仅存于权限 0600 的 .env.local。隧道断开时页面显示数据库不可用，不回退演示数据。隧道需要内网连接，重启电脑后重新建立。

```sh
cd src/frontend
npm ci
npm run dev -- --hostname 127.0.0.1
```

访问 http://127.0.0.1:3000 。API 复用既有默认拒绝、loopback / 明确服务器域名限制及跨站拒绝机制；不提供新的用户身份系统。服务器部署时数据库可直接通过现有 Docker 网络访问，无需开放数据库端口。
