# DIG 客户增长工作台 · 前端交互原型

业务基线来自《整理工作与客户系统需求》对话 2026-11-08 最新的六个用户故事。首页以销售实际动作组织，左侧导航、中央核心业务、右侧日程与增长建议；小窗口下辅助栏顺序移到主内容之后。

## 本机体验

```sh
cd src/frontend
npm ci
npm run dev -- --hostname 127.0.0.1
```

访问 http://127.0.0.1:3000 。首页为全新的交互原型；此前的真实数据工作台保留在 `/legacy`，原有客户路由保持可用。

## 六个业务场景

| 场景 | 原型入口与行为 |
| --- | --- |
| 轻量建档 | 「记一个线索」只必填名称、来源；完整名称匹配才提示重复，提交时再次检查前端集合。重复客户可申请内部协作。 |
| 找到机会 | 「发现机会」展示候选机会、规则依据和沟通切入点。可以忽略并反馈原因、加入培育，或经人工确认后建立商机。 |
| 推进商机 | 四阶段看板、下一步动作、日期、售前资源申请、POC 投入与集团材料准备。阶段可前进或回退。 |
| 维系客户 | 到期提醒、客户经营抽屉、业务合作矩阵、商机与合同项目关联、业务事件时间线。 |
| 经营支持 | 「团队经营」呈现已归集收入与毛利、三类业务的管理重点、经营关注、资源卡点；可分配协同资源。 |
| 内部协作 | 精准查重后仅展示负责人及协作入口；演示申请不自动开放其他客户资料。 |

## 交互与数据边界

- 原型使用 `components/prototype/demo-data.ts` 中合成的企业、人物与经营数据，不访问任何业务 API，不调用真实 AI、飞书、企查查、OA 或财务系统。
- 编辑仅写入当前浏览器的 `dig-growth-prototype-v1` 本地存储。创建线索、需求转化、任务完成、商机更新、协同和跟进等会更新相关界面；刷新后保留。
- 业务连线只出现在「我的客户 → 客户详情 → 业务关联 → POC 与正式项目」。已签约转化的 POC 可关联同一客户、同一来源商机的正式项目；拖动或依次点击两个连接点均可操作。草稿保存在 `dig-growth-prototype-business-links-v1`，不会结转成本或修改审批状态。首页和商机阶段看板不提供自由连线。
- 「原型使用说明」中可恢复初始演示数据。
- 销售与管理切换仅为界面演示，不构成真实身份验证或数据权限。正式实施时需增加服务端权限、唯一约束和并发查重。
- 候选机会与有效商机分开；线索只有确认真实需求后才转为客户和商机。
- 内部商机、集团审批、合同及数据同步分别建模；材料草稿不代表审批通过或合同已签。
- 所有经营金额明确标记为合成快照及已归集口径，不能视为完整财务利润。POC 与项目分别保留业务标识。

## 视觉约定

灰白蓝渐变背景，重要卡片采用约 86%–91% 不透明度的白色，次要卡片为约 34%–48% 不透明度的白色。仅调整背景透明度，正文与按钮不随卡片变淡。深灰主操作 `#292c32`，约 18–24px 圆角卡片、细曲线连接和留白。左侧默认显示窄图标栏，鼠标悬浮或键盘可见焦点进入时，平滑展开为图标加文字；展开覆盖画布，主体卡片尺寸保持稳定。灰蓝表示推进，灰绿表示稳定或已响应，浅赭表示续约与优先事项，灰红表示经营关注。所有状态同时显示文字。

2026-11-09 从参考截图蓝色、红色图形区域取主色样本：蓝色 `#85A2DC`、红色 `#D06B6B`（截图本身存在压缩与抗锯齿）。蓝色表示常规状态和已建立的业务关联，红色标示风险或逾期。页面标题 25–32px，分区标题 18px，正文 14px，标签和辅助信息 12–13px；用深蓝灰文字和更舒展的中文行高保持层级。
